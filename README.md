# Claude Code 工程协作总控 Skill

让 Claude Code 在真实工程项目中按稳定流程协作。用户只需要提出一个简单工程任务，Skill 会自动识别任务类型、读取项目规则、选择工作流、分析代码、执行修改、验证结果，并总结风险。

## 核心价值

这个 Skill 适合把 Claude Code 从单次问答式代码助手，升级为按项目规则工作的工程协作 Agent。

它解决的核心问题：

1. 用户不需要每次编写复杂工程 Prompt。
2. Agent 不会一上来就改代码，会先理解项目和任务。
3. Agent 会优先读取 `CLAUDE.md`，遵守项目规则。
4. Bug 修复会先定位根因和证据。
5. 新功能开发会先分析方案和风险。
6. 重构和高风险操作会先等待用户确认。
7. 修改完成后会运行验证并输出风险点。
8. 可复用经验会逐步沉淀到 `CLAUDE.md`。

## 最高优先级规则

使用这个 Skill 时，所有工程任务都遵循以下优先级。

1. 用户当前明确指令
2. 项目根目录的 `CLAUDE.md`
3. 项目本地规则文件，例如 `CLAUDE.local.md`
4. 当前 Skill 的默认工程协作规则
5. Claude Code 的通用工程判断

如果用户当前指令和项目规则冲突，Agent 应先说明冲突点，再请求用户确认。

## 最重要的执行原则

这些原则优先级最高，适用于所有任务。

1. 先理解项目，再处理任务。
2. 先判断任务类型，再选择流程。
3. 先读取项目规则，再执行修改。
4. 先分析根因或方案，再改代码。
5. 先验证结果，再总结交付。
6. 高风险操作必须先确认。
7. 能用项目真实工具验证，就使用真实工具验证。
8. 每次任务完成后，尽量沉淀可复用经验。

## 什么时候应该使用

### P0：必须使用

以下任务强烈建议使用这个 Skill：

1. Bug、报错、白屏、测试失败、功能异常。
2. 权限、认证、支付、数据库、部署相关修改。
3. 大规模重构、模块拆分、架构调整。
4. 涉及多个文件、多个模块或调用链不明确的任务。
5. 需要先遵守项目规则再执行的任务。

### P1：建议使用

以下任务建议使用这个 Skill：

1. 新功能开发。
2. 前端页面和设计稿还原。
3. 补测试、补边界用例、提高稳定性。
4. 理解复杂模块。
5. 生成项目 `CLAUDE.md`。

### P2：可选使用

以下任务可以使用这个 Skill：

1. 总结当前 diff。
2. 写 commit message。
3. 写 PR 描述。
4. 梳理项目命令。
5. 解释某个文件或函数。

## 使用方式

安装后，可以显式调用：

```text
使用 $claude-code-engineering-auto，帮我修复登录后白屏的问题。
```

也可以直接提出工程任务：

```text
帮我修复登录后白屏的问题。
```

如果 Agent 支持隐式 Skill 触发，它应在识别到工程任务后自动应用本 Skill。

## 安装方式

将整个 `claude-code-engineering-auto` 文件夹复制到 Agent 的 skills 目录。

Codex 常见路径：

```text
C:\Users\<你的用户名>\.codex\skills\claude-code-engineering-auto
```

macOS 或 Linux 常见路径：

```text
~/.codex/skills/claude-code-engineering-auto
```

安装后重新启动 Agent 会话，或刷新 Skills 索引。

## 任务类型和执行效果

### 1. Bug 修复

适合场景：

1. 报错
2. 白屏
3. 测试失败
4. 功能不正常
5. 接口请求失败

示例请求：

```text
使用 $claude-code-engineering-auto，登录后白屏，帮我排查并修复。
```

执行效果：

1. 收集错误现象。
2. 查找日志、报错栈和测试失败信息。
3. 搜索相关代码和调用链。
4. 尝试复现问题。
5. 定位根因并列出证据。
6. 给出 2 到 3 个修复方案。
7. 根据风险决定是否等待确认。
8. 修改代码并运行测试。
9. 输出验证结果和风险点。

### 2. 新功能开发

适合场景：

1. 新增页面
2. 新增导出能力
3. 新增登录功能
4. 新增本地存储
5. 新增聊天记忆系统

示例请求：

```text
使用 $claude-code-engineering-auto，帮我给桌面宠物项目加一个记忆系统。
```

执行效果：

1. 理解功能目标。
2. 扫描现有架构。
3. 找到合适的扩展位置。
4. 分析数据流、状态管理、接口和存储方式。
5. 给出多个方案。
6. 推荐 MVP 方案。
7. 需要用户确认时先暂停。
8. 实现功能、补测试、运行验证。
9. 输出修改摘要和后续扩展建议。

### 3. 代码库理解

适合场景：

1. 接手新项目。
2. 理解项目结构。
3. 理解某个模块。
4. 查找函数调用链。
5. 判断某段代码为什么这样设计。

示例请求：

```text
使用 $claude-code-engineering-auto，帮我看懂这个 Next.js 项目的目录结构和核心数据流。
```

执行效果：

1. 扫描项目结构。
2. 识别技术栈和核心入口。
3. 搜索相关文件、函数、类和调用链。
4. 查看测试文件和文档。
5. 必要时查看 git 历史、issue 或 PR。
6. 输出项目地图、关键模块、调用链和风险点。

### 4. 测试优先

适合场景：

1. 逻辑不稳定。
2. 需要覆盖边界情况。
3. 修复问题时需要补测试。
4. 重要模块缺少测试保护。

示例请求：

```text
使用 $claude-code-engineering-auto，这个登录逻辑不稳定，先帮我补测试再修。
```

执行效果：

1. 找到现有测试。
2. 分析测试覆盖缺口。
3. 设计失败测试。
4. 先写测试。
5. 再修改实现。
6. 运行测试并迭代。
7. 输出新增测试覆盖的场景。

### 5. 前端截图迭代

适合场景：

1. 根据截图实现页面。
2. 还原设计稿。
3. 修复 UI 偏差。
4. 对比页面和目标图。

示例请求：

```text
使用 $claude-code-engineering-auto，根据这张截图实现页面，并截图验证。
```

执行效果：

1. 分析截图或设计稿。
2. 找到前端入口、组件和样式文件。
3. 实现或修改页面。
4. 启动项目。
5. 使用浏览器自动化工具截图。
6. 对比目标图和实际截图。
7. 继续调整直到接近目标。
8. 输出最终差异和可继续优化点。

注意：如果启动调测服务，任务完成后应关闭服务。

### 6. 重构和架构分析

适合场景：

1. 模块职责混乱。
2. 文件过大。
3. 调用链复杂。
4. 需要拆分模块。
5. 需要长期架构方案。

示例请求：

```text
使用 $claude-code-engineering-auto，帮我分析聊天模块怎么重构。
```

执行效果：

1. 理解当前模块职责。
2. 分析调用链、依赖、测试覆盖和风险。
3. 从最小改动、长期架构、测试风险三个方向给出方案。
4. 对比成本、收益和风险。
5. 推荐方案。
6. 用户确认后执行。
7. 分阶段修改并验证。

### 7. `CLAUDE.md` 生成和维护

适合场景：

1. 项目没有协作规则。
2. 项目命令需要沉淀。
3. 团队希望 Claude 按统一规则工作。
4. 多次任务中发现稳定项目经验。

示例请求：

```text
使用 $claude-code-engineering-auto，帮我为当前项目生成 CLAUDE.md。
```

执行效果：

1. 扫描项目结构。
2. 读取 README、package.json、配置文件、测试目录和脚本目录。
3. 提炼技术栈、启动命令、测试命令、构建命令、目录结构和提交规则。
4. 识别高风险操作。
5. 生成 `CLAUDE.md` 草案。
6. 说明哪些规则来自项目文件，哪些是建议。
7. 经用户确认后写入项目。

### 8. Commit 和 PR

适合场景：

1. 总结当前 diff。
2. 写 commit message。
3. 写 PR 描述。
4. 创建 PR 前整理说明。

示例请求：

```text
使用 $claude-code-engineering-auto，帮我总结当前 diff，并写 PR 描述。
```

执行效果：

1. 读取 `git status` 和 `git diff`。
2. 总结修改文件和修改目的。
3. 判断变更类型。
4. 运行必要测试。
5. 生成 commit message。
6. 生成 PR description。
7. 写清楚背景、修改点、验证结果和风险。
8. 推送或创建 PR 前请求用户确认。

## 高风险操作清单

以下操作必须先征求用户确认：

1. 删除文件或目录。
2. 大规模重命名。
3. 安装新依赖。
4. 修改数据库迁移。
5. 修改认证、权限、支付、安全相关逻辑。
6. 修改生产环境配置。
7. 修改环境变量。
8. 推送代码。
9. 创建 release。
10. 部署线上环境。
11. 执行可能破坏数据的 shell 命令。
12. 清空缓存、清空数据库、删除存储桶内容。
13. 改动范围超过当前任务明显需要的文件。

## 完整案例

### 案例一：登录后白屏

用户输入：

```text
使用 $claude-code-engineering-auto，登录后白屏，帮我修一下。
```

Agent 应执行：

1. 判断任务类型为 Bug 根因定位。
2. 检查项目是否有 `CLAUDE.md`。
3. 读取登录流程、路由、状态管理、构建配置和相关入口文件。
4. 搜索错误信息和调用位置。
5. 尝试复现问题。
6. 给出根因证据。
7. 提出修复方案。
8. 如果涉及核心启动流程，先征求确认。
9. 修改后运行启动检查或相关测试。
10. 输出修改文件、验证结果和风险点。

预期输出片段：

```text
当前发现：

1. 相关文件：
LoginPage.tsx
authStore.ts
router.tsx

2. 可能根因：
登录成功后跳转路径和路由配置不一致，导致页面进入空路由状态。

3. 推荐方案：
统一登录跳转路径和路由配置，并增加 fallback 页面。

4. 验证方式：
运行登录流程测试，并手动验证登录后页面跳转。

是否按这个方案修改？
```

### 案例二：新增导出 Markdown 功能

用户输入：

```text
使用 $claude-code-engineering-auto，帮我加一个导出 Markdown 的功能。
```

Agent 应执行：

1. 判断任务类型为新功能开发。
2. 检查 `CLAUDE.md`。
3. 查找现有导出逻辑。
4. 分析数据来源、UI 入口和文件写入方式。
5. 给出实现方案。
6. 实现功能。
7. 补必要测试。
8. 验证导出内容。
9. 汇报修改文件、验证结果和风险点。

### 案例三：生成项目规则

用户输入：

```text
使用 $claude-code-engineering-auto，帮我生成这个项目的 CLAUDE.md。
```

Agent 应执行：

1. 扫描项目结构。
2. 读取 README、配置文件、脚本和测试目录。
3. 提炼项目简介、技术栈、常用命令和目录约定。
4. 提炼默认工程流程。
5. 标注高风险操作。
6. 生成 `CLAUDE.md` 草案。
7. 说明哪些内容来自项目文件，哪些是建议。
8. 等用户确认后写入。
